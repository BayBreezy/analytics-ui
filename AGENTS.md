# AGENTS.md

Nuxt 4 + UI Thing + Tailwind v4 ecommerce admin dashboard on dummy data. Package manager: **bun**.

## Commands

- `bun run dev` · `bun run build`
- `bun run lint` (oxlint) · `bun run format` (oxfmt) · `bun run typecheck` (vue-tsc)
- Before finishing: lint, `format:check`, typecheck and the tests must pass: `bun run test:unit` (fast), `bun run test:api` and `bun run test:e2e` (they build and start the app on port 3222, which takes a few minutes). Add or update a test with every feature: an API spec for an endpoint, an e2e spec for a flow, a unit test for pure logic. Run one spec against a dev server with `PW_BASE_URL=http://localhost:<port> bunx playwright test --project=api tests/api/<file>.spec.ts`.
- Don't commit or push unless asked. Commits are Conventional Commits (commitlint, body lines ≤ 100 chars) with no AI co-author trailer.
- Test rules: specs run one at a time and each starts by resetting the in-memory store (`fresh` fixture), so never rely on data from another test. In e2e use `app.goto` (it waits for hydration), sign in with `signInAs(role)` instead of the form, wait on a condition rather than sleeping, and expect the page to log no console errors (the `diagnostics` fixture fails the test otherwise; allow a message with `test.use({ allowedConsole })`). Unit tests that need auto-imports go in `tests/nuxt/`.
- The user may have a dev server on port 3000. Run your own on another port and never kill processes you didn't start.

## Pinned versions

`typescript` is **6.x** (TS 7 breaks the Vue SFC compiler) and `zod` is **3.x** (`@vee-validate/zod` needs it). Don't bump them.

## Layout

- `app/` UI. `server/` mock API. `shared/` code used by both (zod schemas, types, resource registry).
- `shared/utils`, `shared/types`, `app/composables`, `app/utils`, `server/utils` are auto-imported. Don't import them by hand.
- `app/components/Ui/` is **generated by UI Thing**. Add components with `bunx --bun ui-thing@latest add <name>`, then `bun add` any npm packages it needs (the CLI doesn't install them). Avoid editing Ui files; if you must, say so in your summary, since re-adding overwrites them. Edited so far: `Ui/Vee/Select.vue` (a stable id from the field name, so its label stays connected).

## UI conventions

- Use UI Thing components (`UiButton`, `UiCard`, ...) and lucide icons (`lucide:*`) only. Put icons in a button's default slot, not its `icon` prop (that one only shows on hover).
- Forms: vee-validate + zod with `toTypedSchema` and the `UiVee*` inputs. Reuse the shared schemas in `shared/utils/store-schemas.ts` and `auth-schemas.ts` for both form and API validation.
- Tables: `UiTanStackTable`. Searchable pickers for long lists: `ResourceSelect`. Lists get Export CSV (`server/api/[resource]/export.get.ts`, columns in `shared/utils/csv-columns.ts`) and row selection with bulk actions (`bulk.post.ts`) from `ResourceListPage` for free.
- The command palette (`app/components/App/CommandPalette.vue`) is built from Reka's listbox parts, not `UiCommandItem`/`UiCommandGroup`: those only show an item if it matched the text typed at that moment, which hides results that arrive from the server.
- Charts: wrap `UiApexchart` in `AnalyticsChartCard`, build options from `baseChartOptions()` and take colors from `useChartColors()`. ApexCharts' own default colors are hardcoded blues, so always pass colors.
- Every widget needs loading (`UiSkeleton`), error (`AppErrorState` with retry) and empty (`UiEmpty`) states. Check light and dark mode and a 375px width (no horizontal overflow).

## Routing and auth

- Sidebar links, breadcrumbs and page titles come from `app/utils/navigation.ts`. Every item needs a page: file-based under `app/pages/`, or the resource pages registered by the `pages:extend` hook in `nuxt.config.ts`.
- **Never add a catch-all or top-level `[param]` page.** Unknown URLs such as `/sw.js` must stay 404s (`app/middleware/auth.global.ts` relies on `to.matched`).
- Pages are protected by default. Login/register-style pages set `definePageMeta({ auth: "guest" })`.
- The session is the `auth-session` cookie via `useAuth()`. It is a demo, not real security.
- Roles and permissions live in `shared/utils/permissions.ts` (`hasPermission`, `resourcePermission`). Gate a page with `definePageMeta({ permission })`, a nav item with `NavItem.permission`, a button with `useAuth().can()` (or `useResourcePermissions()` for records), and an API route with `requirePermission(event, ...)`. `server/middleware/auth.ts` returns 401 for every `/api` route without a session except `/api/auth/**`, so scripts and tests must send an `auth-session` cookie (build it from the `/api/auth/login` response).

## Data and the mock API

- All data is faker-generated and held in memory (`server/utils/store.ts`). It resets on restart.
- Customers, orders, products and staff share one API (`server/api/[resource]/`) and four generic pages (`app/resource-pages/`). To add a resource: extend `shared/utils/resources.ts`, its types and zod schema, the store/`server/utils/resources.ts`, then add `List.vue`, `Form.vue` and `Details.vue` in `app/components/<Resource>/`, and register them in `app/composables/useResourceView.ts`.
- Analytics breakdowns are derived from the store (`server/utils/analytics.ts`), while time series are seeded (`server/utils/sales.ts`). Team invitations live in the store too (`server/api/team/`).
- The signed-in user's profile lives in the session cookie (`useAuth().updateUser`), per-browser preferences in cookies (`usePreferences()`), and store-level data (settings, sessions, invitations, billing, support tickets) in the store. `POST /api/settings/reset` re-seeds everything, so any new collection must be added to `seed()`. Store events that should tell the user call `notify()` (`server/utils/notifications.ts`), which respects the in-app switches in Settings.
- A dynamic `$fetch` URL like `` `/api/${resource}/${id}` `` can't use `PUT` or `DELETE` while a static GET-only route such as `export` exists beside `[id]`, because Nitro's typed routes get in the way. Cast the URL `as string`.
- Fetch on the client with `useFetch(..., { server: false })`. Give record pages a key with `useId()` so a page opened right after another never shows stale data.
- List state (page, search, sort, filters) lives in the URL query (`useResourceList`).
